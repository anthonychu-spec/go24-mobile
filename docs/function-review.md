### 4.2 「顯示邊個球場」— 要先改 PGM 設定

**而家 PGM 每間分店只有一個「Pickel Ball」區域，入面有 8 個位**，冇分 Court 1、Court 2。即係 API 只會答「仲有幾多個位」，答唔到「係邊個場」。

要做到 Sterling 咁「Court 1 / Court 2 各自一個 BOOK 掣」，有兩個方法：

| 方法 | 做法 | 好處 | 壞處 |
|---|---|---|---|
| **A（建議）** | GO24 營運喺 PGM 將每個球場開做獨立區域，例如「Pickleball Court 1」「Court 2」，每個整場預約 | App 直接顯示場名；前台喺 PGM 都睇到邊個場；唔會兩個人約同一個場 | 要改 PGM 設定（營運做，唔使寫 code） |
| B | 保持 8 個位，App 自己將位分配落場 | 唔使改 PGM | 前台喺 PGM 睇唔到邊個場；App 同 PGM 資料唔一致，唔建議 |

**已確認（2026-10-24）：Pickleball 8 個位 = 8 個場。**

PGM API 核對結果：預約紀錄（`FacilityBooking`）只記「訂咗幾多個位」（`numberOfBookedSlots`），**完全冇記係邊個位**；`BookFacility` 亦只收「要幾多個位」。所以用而家嘅設定，App 同前台都永遠唔知會員約咗邊個場，兩個人可能去到先發現撞場。**方法 A 係唯一可行做法。**

**營運要喺 PGM 後台做（BOFA、Novotel 各做一次，唔使寫 code）：**

1. 新增區域類型「PICKLEBALL COURT」，**唔開 slots**（`hasSlots = false`）。
2. 每間分店開 8 個區域：「Pickleball Court 1」至「Pickleball Court 8」，類型用上面嗰個。
3. 新增預約定義：整場預約（`isEntireZoneBooking = true`）、45 分鐘、每 15 分鐘一個開始時間。
4. 規則照舊：要有效會籍、免費；每日上限要重新諗（見 4.4 第 2 題）。
5. 為 8 個場設定開放時間（availability）。
6. 舊嘅「Pickel Ball」8 位區域停用。**而家 0 個預約，停用冇影響。**

做完之後，App 每個時間會列出邊幾個場有空，每個場一個 BOOK 掣，同 Sterling 一樣。PGM 前台都會見到每個場嘅預約。

Golf Simulation 嘅 2 個位如果係 2 部模擬器，都要照樣拆開（「Golf Simulator 1／2」）。

## 12. PGM 只讀探 — THE LAB（2026-10-26，backend 第 1 星期 W1-5）

用救返嘅 v2.2 key，**只做 GET**；冇讀會員資料（會員／預約只用 `$top=0` 驗證欄位名，或者用唔存在嘅 `memberId eq 0`）。冇 call `goapi2`。

- LAB 未來 7 日有 **18 堂**，全部喺 zone `71`（成間 club，類型「Club」）。

- 一般人數上限 16、候補 10；THE FORGE (Upper) 上限 1（似係 1 對 1 時段）。
- PGM 回傳時間帶 `+08:00`（例如 `2026-10-26T10:30:00+08:00`），唔使自己轉時區。

### Recovery 設施 — **LAB 喺 PGM 冇設定**

- LAB 只有一個 zone（成間 club），**冇 recovery zone、冇 FacilityBookingDefinition、冇 FacilityBookingRule、冇價錢**。

- **`/odata/Visits` 唔存在（404）**；正確係 `/odata/MemberClubVisits`（`memberId`、`clubId`、`enterDate`、`leaveDate`）。
- 舊 code 嘅日期 filter `datetime'…'` 係 OData v3 寫法，PGM 回 400；要用 v4 `2026-10-01T00:00:00Z`。
- 即係 dashboard 入場次數、活動頁、每月總結 push 一直攞唔到數。已改（commit 見 `STATE.md`）。
